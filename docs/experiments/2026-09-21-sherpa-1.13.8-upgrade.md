# Does sherpa-onnx 1.13.8 change anything spokenpad relies on?

_2026-09-21, worktree branch off `4be5947`. Intel i7-9850H, 6 threads, CPU
provider, other agents building in parallel — every timing below is under
load and is not comparable to the idle figures in `docs/asr.md`._

## Question

Two things at once:

1. Is the jump from sherpa-onnx 1.13.6 to 1.13.8 safe for the code paths
   spokenpad uses — the offline NeMo transducer, the NeMo TDT decoders,
   Silero VAD, Whisper, SenseVoice, and the C API struct layout — and does it
   keep the single static binary?
2. Does 1.13.8 fix `modified_beam_search` on Parakeet TDT
   ([k2-fsa/sherpa-onnx#3267](https://github.com/k2-fsa/sherpa-onnx/issues/3267)),
   which is why spokenpad decodes greedily and has no hotwords today?

The upgrade is also a prerequisite for evaluating Qwen3-ASR, whose
hallucination-on-silence fix landed in 1.13.7.

## Method

- Read the upstream `CHANGELOG.md` entries for 1.13.7 and 1.13.8 and
  classified every line against the code paths spokenpad uses.
- Diffed the published crate sources, `sherpa-onnx` and `sherpa-onnx-sys`
  1.13.6 against 1.13.8, file by file (`diff -r` over `src/`).
- Changed the two `=1.13.6` pins in `Cargo.toml`, the version assert in
  `Transcriber::new`, and the version lines in `docs/asr.md` and
  `docs/rust.md`; rebuilt without `--locked` to update `Cargo.lock`.
- Ran `cargo build --locked --release`, `cargo test --locked --all-targets`,
  `cargo clippy --locked --all-targets -- -D warnings`, `cargo fmt --check`,
  and `cargo test --locked --test e2e -- --ignored` (the real-model e2e).
- Ran `ldd` on the release binary and listed `target/release/` for stray
  shared libraries.
- Ran `cargo run --release --example=eval` and `-- --whole` against the five
  local clips, under `greedy_search` and under `modified_beam_search` with an
  empty vocabulary, on 1.13.6 and again on 1.13.8. Both runs used explicit
  config files (`~/.cache/spokenpad-dev/models/configs/parakeet-tdt-v3-{greedy,beam}.toml`)
  so the user's own config could not affect the result.
- Decoded the last 10.6 s of one recovery capture under both decoding
  methods and both `TrailingSilence` presentations, on both versions, with a
  scratch harness (`examples/model_replay.rs`, not kept; it prints word
  counts, never text).

## Data

- `eval-samples/*.wav`: the five committed eval clips, 100 s total.
- One recovery capture from `~/.local/state/spokenpad/audio/`, the one whose
  lost tail produced the 2026-09-21 greedy-by-default decision. Private; only
  word counts appear here.

## Results

### What changed upstream

Nothing in 1.13.7 or 1.13.8 touches the offline NeMo transducer, the NeMo TDT
decoders, Silero VAD, Whisper or SenseVoice. The entries that matter at all:

| Entry | Release | Relevance to spokenpad |
|---|---|---|
| Update onnxruntime to v1.28.2 (#3935) | 1.13.8 | The only change that can move a number. It did not — see the WER table. |
| Fix Qwen3-ASR hallucinating text on silent audio with hotwords/language set (#3907) | 1.13.7 | Prerequisite for the Qwen3-ASR experiment. |
| Align Qwen3-ASR whisper features to the centered-STFT convention (#3873) | 1.13.7 | Same. |
| Fix data race on shared PRNG in FunASR-Nano and Qwen3-ASR offline recognizers (#3912) | 1.13.8 | Same. |
| Populate `ys_probs` in the **online** NeMo transducer greedy search decoders (#3893) | 1.13.7 | Not our path: spokenpad uses the offline recognizer. |
| Canary / FunASR-Nano / Moonshine v2 / Cohere Transcribe silence-hallucination fixes (#3920, #3921, #3923, #3924) | 1.13.8 | Families spokenpad does not offer. |

### What changed in the Rust crates

`diff -r` over `src/` reports exactly two differing files in each crate, and
in both cases the change is the speaker-diarization
`compute_confidence` field plus documentation:

| Crate | Files differing | Substance |
|---|---|---|
| `sherpa-onnx` | `lib.rs`, `offline_speaker_diarization.rs` | doc text; `OfflineSpeakerDiarizationConfig.compute_confidence` |
| `sherpa-onnx-sys` | `lib.rs`, `offline_speaker_diarization.rs` | `lib.rs` differs **only** by a new module doc comment; the FFI struct definitions are byte-identical |

So no struct spokenpad fills changed layout. `OfflineQwen3ASRModelConfig`
(with its `hotwords: Option<String>`) is present and unchanged in both
versions.

`Cargo.lock` grew by one build-script dependency of `sherpa-onnx-sys`,
`zip 2.4.2` (it now also unpacks an iOS `.xcframework.zip`), and `bzip2`
appears at both 0.4.4 and 0.5.2. Neither links into the binary.

### Static linking

`ldd target/release/spokenpad` after the upgrade lists `linux-vdso`,
`libstdc++`, `libm`, `libportaudio`, `libgcc_s`, `libc`, `ld-linux`,
`libasound`, `libjack`, `libpipewire` — the same set as before, with no
`libsherpa-onnx*` and no `libonnxruntime*`. `target/release/` contains no
shared library beside the executable.

### Word error rate, five clips

Identical to the last digit, per clip and in aggregate, on both paths:

| clip | 1.13.6 VAD | 1.13.8 VAD | 1.13.6 `--whole` | 1.13.8 `--whole` |
|---|---|---|---|---|
| shell-commands | 51.7% | 51.7% | 48.3% | 48.3% |
| cd-home | 100.0% | 100.0% | 100.0% | 100.0% |
| keyboard-layout-reset | 21.1% | 21.1% | 21.1% | 21.1% |
| replacements-critique | 17.8% | 17.8% | 8.2% | 8.2% |
| new-model-review | 0.0% | 0.0% | 0.0% | 0.0% |
| **aggregate** | **18.7%** | **18.7%** | **14.3%** | **14.3%** |

`modified_beam_search` with an empty vocabulary also scores 15.4% on both
versions, per clip as well as in aggregate.

So the onnxruntime 1.27 → 1.28.2 change moved no decode on this corpus.

### The TDT beam-search bug is not fixed

The last 10.6 s of the recovery capture, Parakeet TDT 0.6B v3 int8:

| version | decoding | `Padded` | `Bare` |
|---|---|---|---|
| 1.13.6 | `greedy_search` | 8 words | 7 words |
| 1.13.6 | `modified_beam_search` | **empty** | **empty** |
| 1.13.8 | `greedy_search` | 8 words | 7 words |
| 1.13.8 | `modified_beam_search` | **empty** | **empty** |

Both presentations, both versions. [#3657](https://github.com/k2-fsa/sherpa-onnx/pull/3657),
the pull request that fixes the remaining TDT defects, is still unmerged.

### Checks

`cargo build --locked --release`, `cargo test --locked --all-targets`,
`cargo clippy --locked --all-targets -- -D warnings`, `cargo fmt --check` and
`cargo test --locked --test e2e -- --ignored`
(`real_models_transcribe_the_kennedy_sample`) all pass, as does
`spokenpad check`, which exercises the version assert against the linked
native library.

One wrinkle, unrelated to this change: `tests/pane_window.rs` needs
`target/debug/examples/pane_spike` as a plain binary, and `cargo test
--all-targets` builds examples as test targets with hashed names, so the
first run after a clean build fails with "is missing; build it with `cargo
build --example pane_spike`". Running `cargo build --examples` once makes it
pass. That belongs to the window work, not to this upgrade.

## Conclusion

The upgrade is safe and behaviour-neutral: no struct spokenpad fills changed,
no number moved, and the binary is still one statically linked file. Take it,
because 1.13.7 carries the two Qwen3-ASR fixes that the Qwen3-ASR experiment
needs.

It buys nothing for Parakeet TDT. Beam search still returns nothing for the
same clear speech on 1.13.8, so `greedy_search` stays the default and
hotwords stay unavailable on the current model. Getting hotwords back needs a
different model, which is what
[2026-09-21-parakeet-unified-rnnt.md](2026-09-21-parakeet-unified-rnnt.md)
and [2026-09-21-qwen3-asr.md](2026-09-21-qwen3-asr.md) test.

See [decisions.md](../decisions.md#sherpa-onnx-moves-to-1138-2026-09-21).
